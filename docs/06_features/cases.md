- 상세 배치(UI/UX 자료 CASE-02, 11/17 시연 화면 `/demo/cases` 모양으로 맞춤): 맨 위 머리글은 `케이스 상세`·케이스 번호·한 줄 설명(계좌 · 경보 · 탐지 기간) + 오른쪽에 상태·담당자 배지. 그 아래 **2단** — 왼쪽은 **케이스 개요 + 경보 정보**, 그 밑 **점수 근거**, 오른쪽(23rem)은 **[조사 메모]·[AI 요약]·[처리 이력] 탭**(`CaseNotesCard`)과 **처리 작업**(`CaseActions`). **거래 분석**(합계 + [자금 흐름]·[근거 거래]·[참고 거래] 탭, 처음 열리는 탭은 [자금 흐름] — 조사역이 표를 읽기 전에 돈이 어디서 와서 어디로 갔는지 전체 그림부터 보게 하려고요(설계서 CASE-02-T 탭 순서와 다르면 설계서도 이 순서로 맞춰요 〔확인 필요〕), `CaseEvidenceCard`)는 그 아래 전체 폭 — 그래프 글자가 줄어들지 않고 거래 표가 가로로 잘리지 않게. 카드 제목은 구분선 있는 머리 띠, 명사형으로 맞추고 탭 이름과 탭 안 제목은 같은 문구(SCRUM-325). 탐지 기간은 머리글에만 둬요. 77.5rem(1240px)보다 좁으면 오른쪽 단이 본문 밑으로 내려가 둘씩 나란히, 48rem보다 좁으면 한 줄로 쌓여요. 안 보이는 탭은 지우지 않고 숨겨서 쓰던 메모가 남아요.
- 서버가 준 필드만 표시해요. 등급·HIGH 기준을 프론트에서 계산하지 않아요(`CasePolicy`가 서버에서 정함).
- 처리 이력 한 줄에 담당이 바뀐 대상을 같이 보여요 — 배정 「→ 조사역 1」, 담당자 변경 「조사역 1 → 조사역 2」(서버 `from_assignee`·`to_assignee`의 `display_name`). 값이 없으면(옛 서버·다른 동작) 아무것도 안 붙여요. [SCRUM-348]
- `evidence`와 `context`는 섞지 않아요. 참고 거래 상대방을 혐의자처럼 보이게 하지 않아요(안건 7).
- 화면 집계 숫자(유입·유출)와 STR facts 숫자는 포함 범위가 달라 다를 수 있어요 — 라벨에 무엇을 셌는지 적어요 〔확인 필요: BE 미결 22〕.

### 1.1 근거 질의 — 질의 채팅창 [SCRUM-303, 노션 「조사역 질문 답변 설계 문서」 8절, 계약서 A8·C9]

- 여는 곳: 상세 머리글 **[근거 질의]**(아이콘 + 글자). `available_actions`에 `ASK_QUESTION`이 있을 때만 그려요 — 담당 조사역·승인자(BE SCRUM-302). 역할·상태를 화면에서 계산하지 않아요. 백엔드 `aml.ai.ask-enabled=false`면 서버가 안 넣어서 흔적 없이 사라져요.
- 모양(`CaseAskPanel`): 본문 위 오른쪽 아래에 떠 있는 채팅창(25rem, 36rem 아래에선 화면 폭). 본문 배치를 바꾸지 않고 뒤 화면도 막지 않아요(`role="dialog"` `aria-modal="false"`). 머리 오른쪽 아이콘 버튼 [접기](—)·[닫기](×), Esc로도 닫혀요. 입력은 둥근 칸 + 보내기 화살표([전송]). (설계 8.1은 옆에 붙는 패널이었는데, 11/20 화면 담당 결정으로 떠 있는 채팅창으로 바꿨어요.)
- 문구는 전문적이고 짧게(11/20, 합니다체). 상태별 안내·예시 질의는 `askRules.js` 한 곳에 있어요.

- 처음(질의 이력 0개)엔 안내 + 예시 질의 3개 — 누르면 입력만 채우고 보내지 않아요. 글자 수는 NFC 뒤 UTF-16 길이(서버와 같은 셈), 넘거나 공백만이면 [전송] 비활성. 질의는 앞뒤 공백도 자르지 않고 그대로 보내요. 답 속 계좌는 받은 그대로(`10_BD30` 꼴).
- 기다리는 동안 내 질의 + "근거 확인 중" 카드, 입력 읽기 전용, [전송] 막힘.
- 탭 이동·거래 클릭에도 안 닫히고 [닫기]·Esc로만 닫혀요. 닫으면 강조도 풀려요. **보내는 중엔 [닫기]·Esc가 막혀요**(닫으면 "근거 확인 중" 카드가 사라져 질문이 날아간 것처럼 보여서). [접기]는 돼요.
- **근거 거래 강조**(1차 지금 페이지만): [근거 거래 n건] → 거래 근거 카드가 [근거 거래] 탭으로 바뀌고 `evidence_transaction_ids` 행에 배경색, 그 답 카드에 같은 색 테두리, 표 위 강조 띠. 채팅창은 표를 가리지 않게 접히고, 오른쪽 아래 [질의 창 열기]로 쓰던 입력·강조 그대로 다시 펼쳐요. 탭 구조(SCRUM-247)는 그대로.

- 종료·에스컬레이션은 **사유 입력 + 확인 단계**. 성공 응답 뒤에 상태·이력을 바꿔요. 요청 중엔 같은 버튼 막기.
- [종료]는 버튼 하나 — `CLOSE`면 `close`, `CLOSE_WITH_DRAFT`면 `close-with-draft`. 초안 있는 종료 확인창엔 "초안이 대체됨으로 바뀐다", `NOT_REPORTABLE` 반려 건엔 "반려 코드는 이력에 있고 종료 사유는 세 값 중에서"를 같이 보여 줘요 [BE cases.md 11/3 #39 리뷰 1번].

## 4. 조회·저장 흐름 [예전 「백엔드 기반 설계 보완」 §4, BE flows 02]

1. 목록은 URL에 상태·정렬·페이지. 화면 1페이지 = API `page=0`. 필터가 바뀌면 1페이지로.
2. 상세 성공 뒤 근거 거래를 따로 조회(페이징). 현재 초안은 상세 응답에 합쳐 오는 게 기본안 〔확인 필요: FE-5〕 — **초안이 없는 정상 상태와 초안 조회 실패를 구분**해요.
3. AI 요약은 없거나 사용자가 새로고침을 누를 때 별도 요청(최대 90초, timeout `AI_REQUEST_TIMEOUT_MS` 100초, `03_api.md` §4). 요약 실패가 거래 열람·배정·메모를 막지 않아요. 요약이 지금 입력 기준인지(`is_current`)는 서버 값을 보여 줘요. 응답 없이 끊기면 상세를 다시 불러, 요약이 새로 저장됐으면(`produced_at`이 바뀜) 실패로 띄우지 않아요(SCRUM-315). 다시 불러오는 동안은 실패 안내 대신 "결과를 확인하는 중"을 보여 줘요.
4. 쓰기 성공 뒤 응답이 상세면 캐시 교체, 아니면 상세 재조회 + 목록·이력 무효화.

## 5. 메모 — 동시 수정 [FE 코드 `CaseMemoEditor.jsx`]

지금 들어 있는 동작이에요. 실제 API로 바꿔도 유지해요.

- 메모 입력은 background refetch·409로 **덮어쓰지 않아요.** 쓰기 시작한 기준 `version`을 같이 들고 있어요.
- `CONCURRENT_UPDATE`면 입력 유지 → 최신 내용을 따로 불러와 나란히 비교 → 사용자가 고른 뒤 **새 버전으로 명시적 재저장**.
- 다른 409(`INVALID_CASE_TRANSITION` 등)엔 충돌 비교 화면을 띄우지 않고 코드별 안내 + 재조회.
- 400 `INVALID_REQUEST`의 필드 오류를 입력칸에. 메모는 최대 10,000자(BE 01 §7).
- 미저장 메모가 있으면 새로고침·탭 닫기 때 확인(`beforeunload`), 앱 안 링크로 다른 화면에 갈 때도 확인창([계속 작성]·[저장하지 않고 이동], `shared/ui/useUnsavedLinkGuard`). **브라우저 뒤로·앞으로 가기는 아직 막지 않아요** 〔후속 — `BrowserRouter`라 `useBlocker`를 못 써요〕.
- 저장 응답이 늦게 왔는데 그사이 계정이 바뀌었으면 캐시에 반영하지 않아요(`context.session` 비교).
