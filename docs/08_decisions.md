## 2. 문서끼리 다른 곳 — 이 docs에서 고친 것

원칙: **백엔드 코드 > 백엔드 docs 최신 > 예전 프론트 문서.** 예전 프론트 문서(10/28)가 그 뒤 백엔드 결정과 달라진 곳을 고쳤어요.

| 주제                | 예전 프론트 문서                                | 지금 백엔드                                                                                 | 이 docs                         |
| ------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------- |
| 목록 응답           | `{items, page, size, total_items, total_pages}` | `{items, page, size, total}`, 페이지 수는 프론트가 계산 [BE `PageResponse`, SCRUM-39]       | 백엔드                          |
| 승인·반려 경로      | `{case_no}`·`{draft_id}` 둘 다 언급             | `/approvals/{draft_id}/…` [BE 미결 1, 10/30]                                                | 백엔드                          |
| STR 초안 경로       | `/str/drafts/{id}`와 `/str-drafts/{id}` 혼재    | `/str-drafts/{draft_id}` [BE str 〔초안〕]                                                  | 백엔드                          |
| 메모                | PUT 교체 vs NOTE append "미정"                  | `PUT /cases/{case_no}/notes` + `case_history` NOTE 행 [CASES 명세 v0.5 〔초안〕, BE 미결 8] | 백엔드 〔초안〕                 |
| 상태 전이 에러 이름 | `INVALID_TRANSITION`도 받음                     | `INVALID_CASE_TRANSITION`으로 통일 [BE 03 §2, 10/28]                                        | 백엔드 (옛 이름은 호환만, FE-1) |
| "초안 생성 중"      | 502 AI 오류로 묶음                              | 409 `DRAFT_IN_PROGRESS` [BE 08, 10/29]                                                      | 백엔드                          |
| AI 요청 시간        | "단일 AI 90초 + 서버 재시도 총합 미정"          | 화면 요청 **전체 90초**(재시도 포함) [BE 08, 10/29]                                         | 백엔드                          |
| `/approvals` 권한   | (없음)                                          | GET ADMIN·APPROVER, POST APPROVER [BE 08, 10/29]                                            | 백엔드                          |
| STR 본문 열람       | (없음)                                          | 담당 조사역·승인자만, 그 밖엔 상태·날짜 [서식 안건 4, 10/30]                                | 백엔드                          |
| 상세에 현재 초안    | "프론트가 초안을 별도 조회"                     | str 조회 유스케이스가 조합하는 안 [BE 08, 10/30] 〔확인 필요〕                              | FE-5로                          |
| 버튼 근거           | MSW `allowed_actions`                           | CASES 명세 `available_actions` 〔초안〕 / role+담당+status                                  | FE-4로                          |
| 담당자 위반         | "공통 처리기가 409로 매핑해 403 확인 필요"      | 403 `NOT_ASSIGNEE` 확정 [BE 04 §5]                                                          | 백엔드                          |
| 브랜치 흐름         | 기능 브랜치 → main                              | 기능 브랜치 → develop → main                                                                | 백엔드                          |

## 4. 구현 순서 [예전 「백엔드 기반 설계 보완」 §9]

| 순서 | 범위           | 다 됐다고 보는 기준                                                                                                   |
| ---- | -------------- | --------------------------------------------------------------------------------------------------------------------- |
| 1    | 인증·공통 경계 | local 로그인 → me → 로그아웃, snake_case 변환, 0 기반 페이지, CSRF·401·403·409 분리 — **대부분 됨**, 실서버 확인 남음 |
| 2    | 조사 화면      | 실제 목록·상세·근거 거래, 담당자별 배정·메모·에스컬레이션·종료, 요약 따로 실패, NOTE 이력                             |
| 3    | STR            | 생성 → 수정 → 검증 → 승인 요청, 본문 바뀌면 재검증, 재생성 이력, 입력 보존·동시 수정                                  |
| 4    | 승인           | 승인 대기 읽기 전용, 자기 승인 차단, 사유 반려, 승인 뒤 잠금                                                          |
| 5    | 관리자         | 적재 상태 조회, 배치 순서, 200 일부 실패·실패분만 재처리, 계정 권한 변경 뒤 세션 안내                                 |

API가 확정되기 전에는 지금 mock 흐름을 유지해요. 단계마다 API 모듈·변환·MSW·사용자 흐름 테스트를 같이 바꿔요. **실서버로 세션·쿠키·CSRF와 역할 경계를 확인해야 "연동 완료"**로 표시해요.
