# 04. 로그인·세션·권한 (`features/auth`, `app/queryClient`)

> v0.1 · 2026-10-31 · 초안(팀 확인 중) · 정리 지윤

근거는 BE 04(계정·권한 안내 v0.2 반영본)와 BE flows 05예요. 둘이 프론트 코드와 다르면 백엔드가 맞아요.

## 1. 세션 쿠키 — JWT 없음 [BE 04 §3, FE 코드 `apiClient.js`]

| 단계        | 프론트                                                                                    | 서버                                            |
| ----------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 로그인      | `POST /auth/login {login_id, password}` (JSON, BE PR #20). 실패는 401 `LOGIN_FAILED` 하나 | `SESSION`(HttpOnly) + `XSRF-TOKEN` 쿠키         |
| 로그인 직후 | 응답만 믿지 않고 **`/auth/me`를 다시 조회**해 사용자·CSRF 쿠키 확인                       | `{id, login_id, display_name, role}`            |
| 이후 요청   | 쿠키 자동 전송(`withCredentials`), 쓰기 요청에 `X-XSRF-TOKEN` 헤더(axios `withXSRFToken`) | 세션 → CSRF → URL 역할 → 유스케이스 순서로 검사 |
| 새로고침    | `/auth/me`로 역할을 다시 받음. **localStorage에 사용자·역할 저장 안 함**                  |                                                 |
| 만료        | 401 → 로그인 안내, 현재 URL 유지                                                          | 30분 무활동                                     |
| 로그아웃    | `POST /auth/logout`, 204 본문 파싱 안 함                                                  | 세션 무효화                                     |

- 같은 계정 **동시 세션 1개** — 다른 탭·기기에서 로그인하면 먼저 세션이 끊겨 401이 와요. 정상이에요. 로그인돼 있다가 401로 끊기면 로그인 폼 위에 "다른 곳에서 같은 계정으로 로그인했거나 세션이 끝났어요" 안내를 보여 줘요(`sessionEndedKey`). 로그아웃 버튼으로 나간 경우엔 안 보여요.
- CORS는 백엔드 `local` 프로파일에서만 `http://localhost:5173` 하나. 개발은 Vite 프록시(`/api` → 8080)로 같은 출처라 CORS를 안 타요. 운영은 같은 출처 `/api` 프록시가 기본안 〔확인 필요: FE-9〕.
- 로그인 폼(아이디·비밀번호)은 `AuthPanel`에 있고 운영 빌드에서도 보여요. `mock-login`·계정 선택 UI는 지웠어요. 개발 모드에서만 로컬 계정 안내(비밀번호는 백엔드 `.env`의 `DEV_USER_PASSWORD`, MSW는 `mock-password`)가 붙어요.

## 2. 비로그인일 때 [FE 코드 `AppLayout`, `useSession`]

- `useSession()`(`["auth","me"]`)이 확인되기 전에는 업무 화면을 그리지 않아요.
- `me`가 `null`(확인된 비로그인)이면 **지금 URL을 그대로 둔 채** 로그인 패널을 보여 줘요. 로그인하면 그 화면으로 돌아와요.
- 정식 `/login` 경로를 만들 때도 돌아갈 곳은 **앱 내부 경로만** 보관해요(외부 URL로 튕기지 않게).

## 3. 계정이 바뀌거나 401이 오면 — 업무 캐시 정리 [FE 코드 `queryClient.js`]

이전 사용자의 케이스·메모가 다음 사용자 화면에 남으면 안 돼요. 그래서 세 경로에서 같은 정리(`clearBusinessData`)를 해요.

| 언제                                               | 무엇을                                                                    |
| -------------------------------------------------- | ------------------------------------------------------------------------- |
| 업무 조회가 401                                    | `["auth","me"]`를 `null`로, 업무 Query 전부 취소·삭제, mutation 캐시 삭제 |
| `/auth/me` 응답의 `loginId`가 이전과 다름 / `null` | 같은 정리 (버튼 말고 다른 탭 로그아웃·세션 교체도 잡음)                   |
| 로그인·로그아웃 버튼                               | 요청 **전에** 정리, 성공 후 `me` 재조회                                   |

- "업무 Query" = 첫 칸이 `"auth"`가 아닌 모든 key(`isBusinessQuery`). 새 기능 key도 자동으로 포함돼요.
- 계정이 바뀐 뒤 **늦게 도착한 이전 계정의 쓰기 실패**는 새 세션을 만료시키지 않아요(mutation `context.session` 비교). 쓰기 훅을 만들 때 `onMutate`에서 지금 세션을 `context`에 넣어 주세요.

## 4. 역할과 버튼 [BE 04 §2·§4, BE flows 06]

| 역할     | 코드           | 하는 일                                                                         | 하지 않는 일                                                                                       |
| -------- | -------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 조사역   | `INVESTIGATOR` | 케이스 배정(자기에게)·조사·메모·종료·에스컬레이션, STR 생성·수정·검증·승인 요청 | 승인. 남의 케이스 수정(보기는 됨)                                                                  |
| 승인자   | `APPROVER`     | 승인 대기 보고서 승인·반려                                                      | 조사·초안 작성. **자기가 지금 담당이거나 예전에 담당했던 케이스 승인·반려** [11/7, 백엔드 미결 32] |
| 관리자   | `ADMIN`        | 적재·배치, 룰 기준값, 계정 관리, 담당자 배정·교체, 로그 조회                    | 조사·초안·승인. **STR 본문 보기**(상태·날짜만)                                                     |
| (시스템) | `SYSTEM`       | 배치 행의 작성자                                                                | 로그인 — 화면 어디에도 안 보임                                                                     |

- 한 사람에 역할 하나. **ADMIN이 조사역·승인자 권한을 물려받지 않아요.**
- 버튼은 응답의 `available_actions`(케이스 C2·STR S2 같은 이름)만 보고 켜요. 아래 권한 표는 **기대 동선 설명**이고 화면 코드가 이걸로 계산하지 않아요. 메뉴 노출만 `me.role`로 정해요 [계약서 Q3·Q16 · FR-UI-06, 11/4].
- 조회는 열려 있어요(남의 케이스도 상세는 보임, 열람 기록이 남음). **예외: STR 본문은 담당 조사역·승인자만**(그 밖엔 `access: META_ONLY` — 상태·날짜만). **수정 이력(S4)도 담당 조사역·승인자만**, 그 밖은 403 `NOT_ASSIGNEE`. 없는 `revision_no`는 404 `REVISION_NOT_FOUND` [계약서 S2·S4·Q13, 11/4].

## 6. 관리자 계정 화면 범위 [BE 04 §7, 계약서 3절·5.8, 11/7]

회원가입·비밀번호 찾기 화면은 없어요(관리자가 발급). 화면은 계정 목록 · 발급 · 역할 변경 · 비활성화/재활성화 · 비밀번호 초기화만.

- 상태 변경 경로: `POST /admin/users/{id}/{동사}`. 동사 이름 〔확정〕: `change-role` · `deactivate` · `activate` · `reset-password` [11/7].
- **역할 변경은 조사역 ↔ 승인자만.** 관리자로 바꾸기·관리자에서 바꾸기 둘 다 없어요. 승인자 → 조사역은 열려 있어요.
- **진행 중 담당**이 남은 조사역은 역할 변경이 막혀요 → `change-role`이 409 `ASSIGNEE_HAS_ACTIVE_CASES` + `details.active_case_count`. 진행 중 = `REVIEWING` · `ESCALATED` · `DRAFTED` · `PENDING_APPROVAL` · `REJECTED`.
- **비활성화는 막지 않아요.** `deactivate` 뒤 화면이 진행 중 담당 N건을 알려 줘요(재배정은 관리자가 케이스에서). 목록의 `active_case_count`(조사역만)로 미리 보여 줘요.
- 삭제 버튼 없음 — 퇴사·휴직은 `deactivate`로. 내 계정과 SYSTEM 계정에는 버튼이 없어요.
- 목록 기본값은 활성 계정만, 비활성 보기는 필터로.
- 비밀번호는 발급·초기화 때 말고는 다시 보여 주지 않아요.
- 발급 입력 규칙: 로그인 ID 영문·숫자·`_`·`-` 3~64, 이름 1~50, 비밀번호 8~128. 로그인 ID 중복은 409 `LOGIN_ID_TAKEN`.

→ `06_features/admin.md`.
