## 2. CSS 규칙

- 색·간격·글꼴은 **토큰만** 써요(`var(--…)`). 새 값이 필요하면 `tokens.css`에 먼저 추가.
- 클래스는 kebab-case, 상태는 `is-active`·`is-disabled`처럼 `is-` 접두어.
- 중첩 없이, 인라인 `style`·`!important` 없이.
- 전역 기본 스타일은 `GlobalStyle.js`(styled-components), 레이아웃·기능 스타일은 CSS 파일. 같은 요소에 둘을 섞지 않아요.
- 상태 값(`PENDING_APPROVAL` 등)은 색만으로 구분하지 않고 **글자를 같이** 보여 줘요.
- **화면 셸(SCRUM-280, DashStack 배치 참고)**: 바탕(`--color-canvas` `#f5f6fa`)은 옅은 회색, 카드·입력(`--color-surface`)은 흰색 + `--shadow-card`(옅게 퍼지는 그림자)로 띄워요. 카드 모서리는 `--radius-card`(1rem), 버튼·입력은 `--radius-control`(0.625rem). 사이드바는 바탕 위에 떠 있는 흰 둥근 카드(넓은 화면, 접기·펼치기 — SCRUM-327, 3절)에 메뉴 묶음 제목(업무 공간), 선택 메뉴는 강조색 면(왼쪽 표시 막대 없음 — 카드 밖으로 튀어나와 SCRUM-327에서 뺌), 위 띠는 지금 메뉴 이름 + 오른쪽 역할 칩(로그인 정보·로그아웃). 로그인 전에는 본문 가운데 로그인 카드. 표는 머리 줄 `--color-table-head`, 행은 옅은 경계선만.
- **글자 크기는 단계 토큰만(SCRUM-294)**: `--font-2xs` 0.75rem(12px, 배지·계기판 눈금 등 가장 작은 글자 — 이보다 작게 쓰지 않음) · `--font-xs` 0.8125rem(13px, 표 머리·보조 설명·캡션) · `--font-small` 0.875rem(14px, 라벨·표 본문·보조 버튼) · `--font-body` 0.9375rem(15px, 본문 기본) · `--font-lead` 1rem(16px, 강조 문단) · `--font-section` 1.25rem(20px, 카드·구역 제목) · `--font-title`(`clamp(1.625rem, 1.3rem + 1vw, 2.125rem)`, 화면 제목). 실제 화면 CSS에 16px 이하 글자 크기를 `px`·`rem`으로 직접 적지 않아요. 그보다 큰 글자(점수·건수 KPI 숫자, 로고, 화면 머리 `clamp()` 제목)만 그 자리에 둬요. 시연(`/demo`, `dashboard-demo.css`)은 범위 밖
- **포인트 컬러(`--color-primary` `#0046ff` · `-soft` · `-strong` · `--brand-*`)는 스타일 정리로 바꾸지 않아요.** 바꿔야 하면 따로 이슈를 열고 아래 대비 줄을 다시 계산해요.

## 3. 반응형

- 기본은 모바일 세로 배치. `min-width: 48rem`부터 Grid `17.5rem minmax(0, 1fr)`로 사이드바·본문 분리. 사이드바는 회색 캔버스 위에 떠 있는 둥근 카드예요(SCRUM-327).
- 사이드바 접기·펼치기(넓은 화면만, SCRUM-327): 로고 옆 `«` 버튼 또는 `Ctrl/Cmd + B`(단축키도 넓은 화면에서만 받고, 글 쓰는 칸·확인창에선 무시). 접으면 Grid `0 minmax(0, 1fr)`로 본문이 전체 너비를 쓰고, 왼쪽 위 알약(로고 → `/overview`, `»` → 펼치기)만 남아요. 처음엔 펼친 상태이고 사용자가 접었을 때만 `localStorage`(`dajaba.sidebar.v1`)에 기억해요. 버튼은 `aria-expanded`·`aria-controls="app-sidebar"`, 전환 뒤 초점은 새로 나타난 버튼으로 옮겨요. 좁은 화면은 사이드바가 위에 쌓이므로 버튼·알약을 숨겨요.
- **업무 대시보드 집계 범위는 역할별**(SCRUM-337): 조사역은 **내 담당만**(`GET /cases?assignee=me`) — 카드 「내 담당 케이스」·「보완할 초안」(반려 `NEED_REVISION` — 보완 요청으로 반려돼 **아직 다시 저장하지 않은** 초안. 본문을 저장하면 DRAFTED로 바뀌며 코드가 풀려 빠져요. 즉 **반려 직후 초안만** 세요 — 각주에 「본문을 고쳐 저장하기 시작하면 이 숫자에서 빠져요」 한 줄)·안내 「내 담당 N건 기준」, [전체 케이스] 링크도 `/cases?mine=1`. 승인자·관리자는 지금처럼 조회 가능한 전체. 조사역은 새 케이스를 스스로 맡을 수 없어서(SCRUM-339) 「배정 가능한 미배정」은 넣지 않아요. 다른 담당자 케이스 열람 권한(FR-AUTH-04)은 그대로 — 목록에서 필터를 풀면 보여요.
- **승인자 대시보드의 우선 목록은 승인 대기 보고서**(SCRUM-336): 「지금 바로 확인해야 할 케이스」(점수 높은 케이스) 자리에 「검토를 기다리는 보고서」 — 승인함 P1을 그대로(서버가 요청 오래된 순으로 고정) 앞 3건, 줄마다 초안 번호·케이스·요청 시각·재요청 표시, [초안 검토하기] → `/cases/{case_no}/str`, [승인함 전체] → `/approvals`. 0건이면 「검토를 기다리는 보고서가 없습니다」. 미배정·접수 케이스는 이 자리에 나오지 않아요. 위 카드·차트는 그대로 전체.
- **역할별 업무 흐름 안내**(SCRUM-330): 위 안내 띠는 조사역에게 케이스 확인 → 조사 → STR 작성·검증 → 승인 요청·대기 순서를, 승인자에게 승인함 → 본문·검증 검토 → 승인·반려 순서를 보여 줘요. 케이스 상세·STR 화면에서는 상태를 추측하지 않고 서버 `available_actions`와 응답 상태에 맞는 현재 단계·다음 행동으로 문구를 바꿔요. [전체 흐름]에서는 관리자부터 승인까지 한 건의 전체 흐름과 반려 갈래를 확인할 수 있어요.
- 사이드바를 접어도 대시보드에서 모든 메뉴로 갈 수 있게, 관리자 대시보드에는 켜진(`ready: true`) 메뉴 바로가기 줄이 있어요(`RoleHero`).
- 간격은 Flexbox `gap`, 본문 여백은 rem 토큰, 제목 크기는 `clamp()`.
- 표는 최소 너비를 지키고 **표 영역에서만** 가로 스크롤(페이지 전체가 밀리지 않게).

## 5. 화면 상태 네 가지

조회 화면은 항상 **로딩 · 빈 결과 · 오류(+다시 시도) · 정상** 넷을 그려요. `AsyncState`를 써요.
상세 안의 독립 영역(근거 거래·현재 초안·AI 요약)은 **각자 실패**해요 — 요약이 실패해도 거래 열람·배정·메모는 돼요. 케이스 자체 조회가 실패할 때만 상세 전체를 오류로.
