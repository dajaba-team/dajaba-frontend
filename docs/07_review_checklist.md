# 07. PR 리뷰 체크리스트

> v0.1 · 2026-10-31 · 초안(팀 확인 중) · 정리 지윤

리뷰할 때 보는 항목과 근거 위치예요. **확정 규칙만 리뷰 기준**으로 써요. 백엔드 〔초안〕 명세와 다르게 붙인 건 지적이 아니라 질문으로, 〔제안〕 항목은 `[제안]` 코멘트로만 남겨요.

## 0. 위험도 — 어디부터 꼼꼼히 볼지

| 위험도 | 이런 PR                                                                                                                                        | 보는 깊이                                  |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| **상** | `apiClient`·`queryClient`·`auth`(세션·캐시 정리), 권한·버튼 노출 계산, 승인·반려, 동시 수정(입력 보존), 쓰기 요청 흐름, 실제 API 계약으로 교체 | 전부. 로컬에서 mock·실서버 둘 다 돌려 보기 |
| **중** | 새 화면, 새 API 연동, 공통 컴포넌트(`shared/ui`), 라우트 추가                                                                                  | 아래 체크리스트 전부                       |
| **하** | 스타일, 문구, 문서, 테스트만, 시연(`/demo`)만                                                                                                  | 1·6·7·8절 위주                             |

리뷰 대기열은 **다른 사람을 막는 PR → 오래된 PR → 작은 PR** 순서로 봐요.

## 1. PR 자체 [PR 템플릿, 컨벤션]

- [ ] 대상이 `develop`, 브랜치가 `{type}/SCRUM-xx`
- [ ] 제목·본문에 Jira 키와 링크
- [ ] "확인 방법"에 mock/실서버, 계정, 화면 경로·순서. 화면이 바뀌면 스크린샷
- [ ] CI 초록불 (lint · format · test · build)
- [ ] 한 가지 일, ≤400줄 (`package-lock.json` 제외)
- [ ] 커밋 메시지 `Gitmoji type: 내용`
- [ ] `TODO`에 미결 번호 (`// TODO(FE-3):`)
- [ ] 새 라이브러리면 3줄 사유

## 2. 구조 [`02_structure.md`]

- [ ] 파일이 맞는 폴더에 있음 (`pages`·`components`·`hooks`·`api`)
- [ ] 페이지·컴포넌트가 `apiClient`를 직접 import하지 않음
- [ ] 기능 A가 기능 B의 `api/`를 직접 import하지 않음 (훅으로 조합)
- [ ] `shared`가 `features`·`app`을 import하지 않음
- [ ] 실제 화면이 `mocks/`·`Demo*`·`shared/demo`를 import하지 않음
- [ ] 새 라우트면 `02_structure.md` §3 표와 `06_features` 파일 갱신

## 3. API·데이터 [`03_api.md`]

- [ ] snake_case ↔ camelCase 변환이 API 모듈 안에서 한 번
- [ ] 화면 페이지 1 ↔ API `page=0` 변환, 전체 페이지 `ceil(total / size)`
- [ ] 경로의 사람이 보는 번호에 `encodeURIComponent`
- [ ] 변경 요청에 `version` (또는 `case_version`)
- [ ] `null`·빈 배열을 깨지지 않게 그림
- [ ] 〔임시〕 필드(`has_next`, `allowed_actions`, `CASE_VERSION_CONFLICT`)를 새 코드에 퍼뜨리지 않음
- [ ] API 계약을 바꿨으면 `handlers.js`·테스트·`03_api.md`도 같은 PR
- [ ] AI 요청(요약·생성·검증)은 전용 timeout, 중복 클릭 막기, 자동 재시도·폴링 없음
- [ ] 금액·등급·HIGH 기준·다음 상태를 프론트에서 계산하지 않음

## 4. 상태 관리 [`01_code_rules.md` §4]

- [ ] 서버 데이터를 `useState`·Zustand에 복사하지 않음
- [ ] mutation `retry` 없음, 낙관적 상태 변경 없음 — 성공 응답 뒤 캐시 교체·무효화
- [ ] 편집 중 입력이 refetch·409로 덮이지 않음
- [ ] 필터·페이지가 URL에 있음 (새로고침해도 유지)
- [ ] 쓰기 훅 `onMutate`가 `context.session`을 넣어 늦은 응답을 걸러냄
- [ ] 새 Query key가 `"auth"`로 시작하지 않음 (계정 전환 때 지워져야 함)

## 5. 권한·에러 [`04_auth_session.md`, `03_api.md` §3]

- [ ] 버튼 노출이 `role` + 담당자 + `status` (+ 초안 상태·검증)로 계산됨. 권한 표 번호와 맞음
- [ ] ADMIN에게 조사·승인 버튼이 보이지 않음, STR 본문이 담당·승인자에게만
- [ ] 승인자 본인 담당 케이스에 승인 버튼이 없음
- [ ] 에러 분기가 `error.code` 기준, 문구는 `getErrorMessage`
- [ ] `CONCURRENT_UPDATE`만 충돌 비교, 다른 409는 코드별 안내 + 재조회
- [ ] 실패 뒤 사용자 입력이 남아 있음
- [ ] 401에서 업무 캐시가 지워지고 URL이 유지됨
- [ ] 되돌릴 수 없는 버튼(종료·반려·승인)에 확인 단계와 필수 사유

## 6. 보안 [`01_code_rules.md` §6]

- [ ] 토큰·역할·본문을 localStorage/sessionStorage에 저장하지 않음
- [ ] `console`에 금액·계좌번호·고객명·본문·메모 없음
- [ ] 계좌번호를 복원·조합하지 않음
- [ ] AI 본문을 HTML로 그리지 않음
- [ ] `VITE_*`에 비밀값 없음, 주소 하드코딩 없음

## 7. UI·접근성 [`05_ui.md`]

- [ ] 로딩 · 빈 결과 · 오류(+다시 시도) · 정상 네 상태
- [ ] 상세 안 독립 영역이 각자 실패 (요약 실패가 상세 전체를 막지 않음)
- [ ] 색·간격은 토큰, 인라인 `style`·`!important` 없음
- [ ] label·caption·scope·`aria-current`·`aria-live`, 키보드로 조작 가능
- [ ] 상태가 색뿐 아니라 글자로도 보임
- [ ] 모바일 폭에서 페이지 전체가 가로로 밀리지 않음 (표만 스크롤)

## 8. 테스트 [`01_code_rules.md` §8, `09_test_deploy.md`]

- [ ] 정상 1 + 경계 1 + 실패 1, 사용자 흐름으로
- [ ] 역할·이름으로 요소 찾기 (`getByRole`)
- [ ] 새 API 요청이 `handlers.js`에 있음 (`onUnhandledRequest: "error"`)
- [ ] 권한 PR이면 "버튼 숨김"과 "직접 호출 시 403/409 안내" 둘 다

## 9. 문서

- [ ] 화면·버튼·API가 바뀌면 같은 PR에서 `06_features/*.md` 갱신
- [ ] 새 에러 코드를 다루면 `03_api.md` §3 표와 `getErrorMessage` 둘 다
- [ ] README "지금 들어 있는 것" 표에 영향이 있으면 갱신
- [ ] 백엔드 계약과 다른 점을 발견하면 `08_decisions.md` 미결에 한 줄

## 10. 리뷰 코멘트 쓰는 법 [컨벤션, BE 07 §11]

근거와 개선 방향을 함께 쓰는 **제안형**으로 써요.

```
[반드시] (파일:줄) 무엇이 왜 문제인지 — 근거: 01_code_rules §4 / 규칙 세 줄 2
         이렇게 바꾸면 돼요: …
[제안]   …
[질문]   STR 명세 〔초안〕과 필드 이름이 다른데 의도한 건가요?
[좋아요] …
```

- `[반드시]`는 **확정 규칙 위반**에만 써요. 〔초안〕과 다른 건 `[질문]`.
- 요청자는 코멘트마다 반영 여부나 의견을 남겨요.
- 서로 다른 사람에게 같은 지적이 두 번 나오면 `02_structure.md` §2 자동 검사 후보(ESLint `no-restricted-imports`)로 올려요.
